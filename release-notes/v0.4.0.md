This is a minor release. Downloads now respect each mirror's published rate-limit and download budgets instead of finding them by being refused, every queued run shares what the mirrors have already said, and the desktop app shows an estimated time remaining while it downloads. It's in early access: versions stay at 0.x until it's stable enough for 1.0.0.

osu-shelf is an unofficial community tool, not made, endorsed or supported by ppy (osu!) or osu!Collector.

## What's new since 0.3.1

- **Mirror budgets are respected before they run out.** The downloader reads the rate-limit and download-budget headers that mirrors such as catboy.best and osu.direct send, including on redirects, and holds a request back before it would exceed the mirror's remaining requests or bytes. osu!'s own servers get a static 10-per-hour quota when they publish no headers. Waiting for a budget is kept separate from backing off after a 429, so a run no longer has to hit a mirror's limit to learn about it. A mirror's headers, including its bearer token, are never forwarded to another host.
- **Queued runs share one view of the mirrors.** The desktop app and the terminal app each keep one scheduler for mirror spacing, cooldowns and budgets, and give it to every run they start. A second collection queued behind the first therefore starts knowing which mirrors are cooling down or running low, instead of starting from zero.
- **The desktop app shows an estimate.** While a collection downloads, the progress line shows "about N min left", or "under a minute left" / "over a day left" at either end. Hovering it lists the mirrors that are cooling down or blocked by a budget, and how long each has left. The estimate is capped at seven days and refreshed about twice a second. The terminal app keeps its speed-based estimate and doesn't show the mirror-aware one yet.
- **Wide windows use the space.** Find puts its form beside a grid of results, and Settings splits into two columns once the window is wide enough. Pages choose their own width instead of the app capping everything at 1080px, and below 1000px the sidebar becomes a compact top bar, so the 820x560 minimum window no longer has a full-height nav taking up room.
- **Setup lists every osu!lazer install.** When more than one lazer data folder is found, Setup lets you pick which one to read — for example a Torii build rather than whichever folder changed most recently. Automatic detection still uses the newest.
- **A library that can't be read now says so.** If the osu! library can't be read before a download, the run warns you (a warning toast in the terminal app) instead of silently skipping the "already have" check. The download still goes ahead.
- **Smaller fixes:** the Find header's "Showing N of M" now counts only visible results, with the number hidden by "Hide maps I already have" kept on the checkbox, and on nzbasic searches the result order now explains what relevance means there (newest ranked first).

## Known limits

- **The estimate is a lower bound.** It says when the mirrors can send every outstanding request, not how long those transfers then take to arrive, so the real finish can come later. It also knows nothing about a mirror going down.
- **The Windows and macOS builds haven't been run on a real Windows PC or Mac yet.** That covers the installers, the Windows one-line installer, and finding osu!lazer and Torii folders on those systems. They're built and checked automatically; please [open an issue](https://github.com/DesireThings/osu-shelf/issues/new) if something doesn't work.
- **macOS:** Apple Silicon only; there are no Intel Mac builds.
- **The desktop app doesn't update itself.** To update, download and install the new version over the old one. The terminal app does update itself.
- **Find in the desktop app** lists map sets only: there's no per-difficulty view yet, and searches through osu! don't show download sizes.
- **Update in the desktop app** lists missing map sets by number (each links to its osu! page), not by title, and can't yet mark a set as already installed or check failed maps again.

## Checking the files

`SHA256SUMS` lists the SHA-256 of every file in this release. On Linux or macOS, in the folder with your downloads: `sha256sum -c SHA256SUMS --ignore-missing` (on macOS, `shasum -a 256 -c SHA256SUMS --ignore-missing`).
